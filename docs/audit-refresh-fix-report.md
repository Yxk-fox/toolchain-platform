# 全站写操作后页面自动刷新问题排查报告

日期：2026-11-06　|　提交：`a1102b7`（前序：`ced2d99` 网址大全页修复）　|　状态：已修复并推送

## 一、问题现象

- 各页面完成添加/上传、更新/编辑、删除操作后，页面不刷新，需手动刷新（F5）才能看到最新数据
- 自研程序页点击删除后行不消失，用户以为"删除失败"（实际后端已删除成功）
- 上一轮已修复网址大全页（环境增删改），本轮扩展排查全站所有页面

## 二、根本原因（双重拦截）

1. **路由守卫拦截**：`renderRoute(route)` 内部有"同路由不重复渲染"守卫——
   写操作成功后调用 `renderRoute('programs')` 时，当前路由本来就是 `programs`，
   守卫直接 `return`，`render` 逻辑根本不执行（app.js `renderRoute` 函数）。
2. **数据缓存拦截**：即使绕过守卫，`loadAllData()` 有 2 分钟 TTL 缓存，
   重渲染拿到的仍是旧数据。

筛选/Tab 切换等少数调用点在调用前手动写了 `_currentRenderRoute = null` 绕过守卫，
但绝大多数写操作没有——这就是"有的地方正常、有的地方不刷新"的原因。

**删除"失败"的本质**：后端 `DELETE /api/programs/{id}` 实测返回 200 成功；
是前端删除成功后页面不重绘，行依然在表格里，造成"删除失败"的视觉假象。

## 三、修复方案

新增统一刷新函数（app.js）：

```js
function refreshCurrentPage() {
  _currentRenderRoute = null;   // 重置守卫，允许重渲染
  invalidateDataCache();        // 数据缓存失效，强制重新拉取
  renderRoute(getRoute());
}
```

将以下 **24 处写操作完成点** 统一替换为 `refreshCurrentPage()`：

| 页面 | 修复点 |
|---|---|
| 软件管家（tools） | 工具添加、编辑、删除、安装包删除（4 处） |
| 脚本管理（scripts） | 上传、编辑、删除 + 手动刷新按钮（4 处） |
| 自研程序（programs） | 上传、编辑、删除 + 手动刷新按钮（4 处） |
| 我的收藏（favorites） | 快捷入口添加、删除（2 处） |
| 用户管理（users） | 创建、更新、删除、授权、收回授权 + 刷新按钮（6 处） |
| 系统设置（settings） | 分组配置、工具箱分组、矿区分组、菜单顺序保存（4 处） |

保持不变的调用点：网址大全 4 处（上轮已修复）、tools 页筛选/Tab 切换 3 处
（已自行重置守卫）、登出流程 2 处（非写操作）。

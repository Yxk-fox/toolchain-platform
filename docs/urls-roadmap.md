## 二、迭代方向

### 阶段一：功能扩展（近期，1-2 个迭代）

1. **可用性监控增强**
   - 巡检历史曲线：记录每次巡检延迟，卡片悬停显示最近 24h 可用率（如 99.2%）
   - 响应耗时展示：状态点旁显示 TCP/HTTP 毫秒级延迟，慢响应黄色预警
   - 巡检失败原因分类（超时/拒连/DNS 失败），点击状态点弹出详情
2. **链接健康深度检查**
   - 域名类条目支持 HTTP 状态码检查（200/301/403 分级展示）
   - 证书到期监控：HTTPS 站点展示证书剩余天数，7 天内到期红色告警并联动告警中心
3. **搜索与筛选增强**
   - 分组/矿区筛选下拉；按状态（在线/离线）快捷过滤
   - 搜索结果支持回车打开第一项；高亮匹配文本
4. **卡片信息增强**
   - 子链接支持图标与描述；最近访问时间展示（联动访问历史）
   - 环境条目支持"一键复制完整 URL"（当前仅复制 IP/域名）
5. **批量操作**：多选卡片批量删除/移动分组（软件管家页已有勾选交互可复用）

### 阶段二：性能优化（中期）

1. **巡检架构**：当前巡检为全量轮询，条目增多后耗时线性增长
   - 改为异步并发巡检（asyncio + 连接池，单轮 ≤5s 目标）
   - 巡检结果写入独立缓存层（内存 + JSON 双写），避免渲染路径上同步探测
2. **前端渲染**：条目超过 50 个后一次 render 全量 DOM 会卡顿
   - 引入分组折叠（默认展开常用组）+ 虚拟滚动备选
   - 状态更新改为 DOM 精准打点（仅更新状态点/延迟文本），不整页重绘
3. **数据层**：envs 全量下发改为 `?fields=min` 轻量列表 + 详情按需拉取
4. **缓存策略**：巡检状态用 SSE/轮询局部推送替代整页数据重拉

### 阶段三：用户体验提升（中长期）

1. **个性化**
   - 常用置顶：按访问历史自动生成"常用入口"行（首页快捷入口已有雏形，迁移为算法排序）
   - 用户自定义布局：分组折叠状态、默认筛选偏好持久化到账户
2. **移动端适配**
   - 响应式栅格 + 大拇指友好的卡片操作（长按唤起操作菜单）
   - 拖拽排序已支持触摸（Pointer Events），补充移动端手柄常显（已做）
3. **无障碍与国际化**
   - 状态除颜色外增加文本/图形双标识（色弱友好）
   - 英文界面支持（i18n 词条抽取）
4. **安全感设计**
   - 离线条目显示"上次在线时间"而非仅"离线"
   - 删除二次确认改为可撤销操作（回收站已有基建，接入环境删除）

### 阶段四：平台化演进（远期）

1. **开放集成**：环境信息支持从 CMDB/云平台自动同步（AWS/阿里云标签自动生成条目）
2. **Webhook/订阅**：环境上线/离线事件推送飞书群机器人（告警中心已具备后端基础）
3. **服务地图**：与服务目录页联动，可视化环境承载哪些服务（依赖图已有数据结构）

## 三、优先级建议（按投入产出比）

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 巡检历史+可用率、证书到期监控 | 运维价值最高，告警中心可复用 |
| P0 | 批量操作 | 多环境管理刚需，交互成本低 |
| P1 | 筛选/搜索增强、URL 一键复制 | 低成本高频收益 |
| P1 | 巡检异步化 | 条目增长后的稳定性保障 |
| P2 | 常用置顶、移动端 | 体验提升，数据基础已具备 |
| P3 | CMDB 同步、服务地图 | 依赖服务目录页成熟度 |

## 四、风险与依赖

- 巡检异步化需后端并发改造，注意 JSON 文件存储的写锁（当前 threading.Lock 方案在高频写下有竞争风险，建议巡检状态独立存储）
- 证书监控需要 outbound 443 访问，内网环境需确认目标域名可达性
- 移动端改造涉及全局样式，建议先做网址大全单页试点再推广
